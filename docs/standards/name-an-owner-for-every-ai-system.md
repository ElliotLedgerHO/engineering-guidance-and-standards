Teams must record a named owner for every artificial intelligence (AI) system they build, configure or use. The owner is accountable for what the system does and what it costs.

An AI system is any machine-based system that uses AI to generate outputs, such as content, recommendations or decisions, from the input it receives. This includes AI assistants, AI agents and AI features built into existing applications. This standard applies to all teams that build, configure or use AI systems.

---

## Requirement(s)

- [Every AI system MUST have a named owner in an up-to-date record](#every-ai-system-must-have-a-named-owner-in-an-up-to-date-record)
- [An agent used across teams MUST have one accountable team](#an-agent-used-across-teams-must-have-one-accountable-team)
- [The owner MUST agree limits on AI costs before use](#the-owner-must-agree-limits-on-ai-costs-before-use)
- [Teams MUST evaluate and test a skill before sharing it with other teams](#teams-must-evaluate-and-test-a-skill-before-sharing-it-with-other-teams)

### Every AI system MUST have a named owner in an up-to-date record

Teams must keep a record that names the individual or team accountable for each AI system. The record must be easy for others to find. Teams must update it when the owner changes.

### An agent used across teams MUST have one accountable team

When an agent works across more than one team, a single team must be accountable for it. Shared accountability can leave nobody responsible when something goes wrong.

### The owner MUST agree limits on AI costs before use

Before a team starts using an AI system, its owner must agree cost limits. The limits must be measurable and time-bound, for example a monthly budget.

AI usage costs can grow quickly and are hard to predict. Agreeing limits in advance helps teams check that the benefit is worth the cost.

### Teams MUST evaluate and test a skill before sharing it with other teams

A skill is a reusable set of instructions, prompts or tools that changes how an AI assistant or agent behaves. Before a team shares a skill with another team, the team must evaluate and test it to confirm it behaves as expected. The evaluation must include prompt evaluation – running the skill against a set of example inputs and checking its outputs.
